The Development of CCode

September 18, 2025 - The Beginning

This project started with my curiosity about C and my excitement for the language.

A while back, I had written my own JSON single header library, and I wanted to put it to the test in a real project. I had always been interested in building a code editor, so I decided to give it a shot.

When I learned that the Language Server Protocol (LSP) uses JSON-RPC for communication, I realized it would be the perfect opportunity to test my library in practice.

At the time, I hadn’t switched to Linux yet, so I chose PDCurses for terminal handling. I also wanted to keep dependencies to a minimum, so I started with two simple but useful libraries:

stb_ds.h - dynamic arrays and hash maps.
nob.h - an excellent “build system” and a convenient way to handle filesystem operations across platforms.

The initial version was fairly simple, consisting of just two layers: the code layer itself and a console layer with a Vim-like interface.

Even in this early version, I established a convention that would stick with the project: the CCode struct, created in main(), held a dynamic array of pointers to layers.

Each layer followed a simple structure:

typedef struct {
    LayerType type;
    bool consume_input;
    void* layer_data;
} Layer;

Depending on the layer’s type, layer_data was cast to either LayerConsoleData* or LayerCodeData*. This gave me a straightforward way to organize different parts of the application while keeping their implementations separate.

After many commits focused on bug fixes and new features, I implemented the first additional layer: the tree, a built-in filesystem explorer.

March 28, 2026 - Better Syntax Highlighting

I replaced my naive syntax-highlighting implementation with Tree-sitter.

This was a significant improvement, making it possible to support more programming languages while also making the system much easier to extend.

April 3–7, 2026 - Bringing LSP into the Editor

This was when I started working on actual language-server integration.

On April 3, I created the C-LSP-Client repository, along with a demo that connected to and communicated with an LSP server - clangd, in this case.

The following day, I managed to integrate the client into CCode. By April 7, basic type hints and diagnostics were already working inside the editor.

Since then, I’ve added support for more language servers and made the process of integrating a new one into the editor much easier.

Present Day - Still a Passion Project

CCode is still my passion project. I keep coming back to it whenever I get an idea for a new feature or simply feel like tinkering with some C.

My goal is to get it to the point where I can use it instead of Sublime Text. Honestly, I think I’m getting close and I might have already crossed that threshold.

The editor already has most of the essentials you’d expect, including search, split views (for code), LSP integration, code completion, and a floating tree view (my personal favorite), among many other features.

If you’ve made it this far, I’d love for you to give CCode a try! Hopefully, building it is straightforward enough. I’d also really appreciate any feedback you have. If you encounter a bug, feel free to open an issue.
